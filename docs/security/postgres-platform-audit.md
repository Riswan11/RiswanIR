# PostgreSQL preview audit inventory

Baseline is PR #40 squash commit `783d4bc`. The hosted preview is limited to development and testing. This inventory identifies the repository of record by domain. A request can produce a security authorization decision, a resource lifecycle event and a receipt, each with a different purpose.

| Domain and authority | PostgreSQL persistence and scope | Access and transaction boundaries |
| --- | --- | --- |
| Identity, browser sessions and workload lifecycle. `identity_repository.py` and `postgres_identity.py` | `riswan_auth.authentication_events` and `identity_status_history`. Identity and actor scope includes pre-tenant events. Browser session and workload enrollment rows hold current state. | Identity runtime uses restricted access under migration 0013. Identity revocation and required audit persist together. Authentication data is excluded from tenant timelines. |
| Authorization and role administration. `authorization_repository.py` and `postgres_control.py` | `riswan_control.authorization_audit_events`. Records actor, tenant, action, resource, outcome, reason and policy version. | Evaluator records denies and privileged allows. Required audit failure denies access. Control runtime has append access under migration 0014. |
| Organizations, tenant lifecycle, membership and invitations. `tenancy.py` | `riswan_control.organization_audit_events`. Tenant-bound records carry event ID, actor, operation, target, request and time. | Control transaction includes required lifecycle audit. The new audit API requires current organization permission and MFA. It projects only timeline fields and verifies cursor ownership. |
| Secrets, versions, rotation, revocation, cloud credentials and provider binding. `postgres_secrets.py` and the platform secrets service. | `riswan_control.secret_access_events`. Tenant and product scope includes workload and provider context where applicable. Provider instances, bindings, lease and rotation state live in control tables. | Control role and forced RLS apply under migration 0015. Audit stores outcomes and authorized references. External provider effects use the existing durable operation and reconciliation contract. |
| Integration and collection. `postgres_collections.py` and hosted collection routes. | `riswan_data.collection_runs` is an operational receipt scoped to tenant, product and integration. Recent receipts preserve workload, request and correlation identifiers. | Collection publication, checkpoint and receipt commit in the product transaction. Migration 0019 records initial registration with workload, provider instance and correlation in the registration transaction. Credential audit stays in its control repository. Provider executions can precede database publication. |
| Protected-object mutations. `postgres_objects.py` | `riswan_data.protected_object_audit` records object UUID, scope, actor and actor type, request, correlation and database time. | Restricted product role has column-level insert and forced RLS. The database trigger records row insertion and deletion in the same transaction. Its projection excludes envelope contents. Direct audit retrieval is reserved to privileged database access. |
| Legal holds. `postgres_cases.py` | `riswan_data.investigation_hold_audit` records case and scoped actor attribution alongside hold state. | Authorized product transaction owns the mutation and history under migration 0005. |
| Investigation and analyst history. `postgres_cases.py` | `riswan_data.case_memory_history` preserves investigation memory feedback and retrieval history. Case custody and evidence revisions preserve evidence lineage in the product domain. | Product RLS and scoped investigation routes apply. Investigation custody establishes evidence lineage. It has a separate purpose from platform access auditing. |

The migration role owns the tables. Runtime roles are separate and lack ownership and BYPASSRLS. The application establishes transaction-local scope on pooled connections. A holder of runtime database credentials can set custom PostgreSQL scope settings, so treating those credentials as trusted remains part of the deployment boundary. Append-only runtime privileges provide protection against rewriting or deleting recorded events. Privileged administrators retain database-level control. Retention, legal-hold-aware disposal and verified erasure remain Checkpoint C.

Workstation SQLite remains available under its explicit configuration. The fully PostgreSQL preview composes PostgreSQL identity, tenancy, authorization and product repositories. The compatibility configuration selecting SQLite controls must be assessed separately from a PostgreSQL outage. The investigation compiler also uses ephemeral SQLite staging. Application logs remain operational diagnostics.

## Acceptance work

The tenant timeline currently covers organization events and request filtering. An authenticated product, actor, workload, integration and resource audit retrieval design needs separate permissions and bounded query verification. Organization, control and product connections have separate transactions. A control success audit records authorization to attempt a product operation. Product receipts, hold history and protected-object audit record committed effects within their product transactions. Administrative integration enable/disable changes and future configuration update paths need separate lifecycle audit and rollback verification. Broader authenticated outage, restart and sensitive-material regression tests and the query-plan matrix remain acceptance work.
